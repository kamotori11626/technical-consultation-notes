# 構成とデータの流れ

## デモ

ブラウザ → Workerのログイン確認 → 画面・保護対象スクリプト。

ブラウザの確認済み指示文 → WorkerのOrigin・CSRF・入力上限確認 → D1の月間試行枠を原子的に予約 → GeminiのcountTokens → generateContent → 出力形式確認 → 編集の競合を確認 → 画面へ反映。

実行回数はD1に、試し入力はブラウザのタブ内に保存します。D1に相談本文やDOCXは保存しません。ログインの試行制限も同じ表を使用します。公開サイトのCookieはHttpOnly・Secure・SameSite=Strictで、署名付き、有効期間2時間です。

DOCXはブラウザ内でOOXMLをZIPにまとめます。元のテンプレートは `record-template.js` に埋め込んでいます。和暦への変換は出力時に行い、入力の年月日自体は変更しません。

ローカルプレビューはHTTPで手元だけからアクセスできるようCookie名等を変え、実AIを無効にした開発用の仕組みです。本番認証の代替として外部へ露出させないでください。

## ローカル版

ブラウザ → localhost限定Pythonサーバー → SQLiteへの記録保存・更新・一覧。

Geminiへ送るのは生成段階ごとの指示文です。DOCXの基本情報欄はAI用指示文に混ぜない構成ですが、自由記述の本文に個人情報を入力した場合の自動匿名化を保証するものではありません。

PDFはLibreOfficeを別プロセスで実行します。月次Excelは `@oai/artifact-tool` によりテンプレートへ記入し、Pythonで印刷設定や式キャッシュを補正します。これらの実行環境は元のMacに依存します。
