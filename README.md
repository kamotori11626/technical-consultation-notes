# 技術相談の調査メモ

食品加工の技術相談を題材に、資料探索の準備、原資料との照合、回答メモ、対応後の記録票作成を一つの流れにした個人試作です。AIの出力をそのまま確定回答とせず、担当者が根拠を確認してから次の工程へ進む構成にしています。

**学習・個人制作の成果物です。勤務先の公式サービスや、業務導入の実績を示すものではありません。**

説明・デモ：<https://consultation-research-demo.kamotori.chatgpt.site/>

説明ページはログインなしで閲覧できます。操作デモの認証情報はこのリポジトリに含めません。リポジトリは移行時点では非公開であり、非公開のままでは採用担当者はコードを閲覧できません。

## 制作の背景と担当範囲

食品研究・品質管理分野での本人の業務経験を題材に、相談条件の整理、資料との照合、回答、記録作成のつながりを考えました。その業務経験と、本アプリの個人制作は区別しています。

制作では生成AIを用いてコード・文書案の作成や修正、テストの実装を進めています。本人が示した業務上の要件や様式の修正指示と、AIを使った実装・検証を組み合わせた成果物です。コードをすべて独力で記述した実績としては扱いません。

業務への導入、相談対応時間の短縮、回答品質の向上などの効果は未検証です。本リポジトリのテスト結果は、実装の特定の動作を確認したものであり、実際の技術回答の正確性を保証しません。

## 二つの版

| 項目 | `demo/` 採用向けデモ | `local-app/` ローカル版の匿名化コピー |
|---|---|---|
| 用途 | 架空の相談による操作体験・コードレビュー | 元のローカル設計の確認・手元での実行 |
| 基準 | 公開中のSites版2に対応するソース | 元の `prototype/` から許可リストで選んだコード |
| 実行環境 | JavaScript、Sites上のWorker、D1 | Python標準ライブラリ、HTML/JavaScript、SQLite |
| 認証 | 共通ログイン、署名Cookie、APIのCSRF検証 | localhost限定、Host・Origin・アプリトークン確認 |
| 記録保存 | タブ単位の `sessionStorage`。他の閲覧者と共有しない | 手元のSQLite。コピーには既存DBを含めない |
| DOCX | ブラウザ内で生成。右上の日付は和暦 | ブラウザ内で生成。元の出力仕様を保持 |
| DOCX取込・PDF・月次Excel | 対象外 | 実装あり。PDF・Excelは追加環境が必要 |
| AI | 公開版は旧モデルで失敗を確認。接続修正は未完了 | 設定モデルを使用。現在の実API成功は本移行では未確認 |

所属の固定表示は匿名化コピーでは「デモ研究所」に置き換えています。元のローカルアプリ、実DB、稼働中のサイトはこの移行で変更していません。

## まず手元で試す

Node.js 22以降を使用します。デモには追加のnpm依存パッケージはありません。

```sh
git clone https://github.com/kamotori11626/technical-consultation-notes.git
cd technical-consultation-notes/demo
npm test
npm run dev
```

`http://127.0.0.1:8776/` を開きます。ローカルプレビュー専用のIDは `preview`、パスワードは `preview-only` です。これはソースを取得した人が試すための固定値で、公開サイトの認証情報とは異なります。ローカルプレビューでは実AIを呼び出さず、利用回数はメモリ内だけに保持します。

「架空の見本を読み込む」で各欄を確認できます。記録票の出力には、回答済みと内容確認のチェックが必要です。見本は操作説明用であり、実在する論文・試験結果・相談記録ではありません。

元のPython版を試す場合：

```sh
cd ../local-app
python3 server.py
```

`http://127.0.0.1:8766/` を開きます。キー未設定でも手動入力と文書作成を試せます。実AIの使用には自分のGemini API設定が必要です。課金や外部送信を伴うため、架空の情報だけで確認してください。PDF・Excelの追加条件は[実行手順](docs/RUNNING.md)に記載しています。

## コードで確認できる点

- 原資料・回答案・照合結果を分け、担当者の確認を経て回答メモを作る画面遷移
- AI処理中に入力が変わった場合の自動反映中止
- 記録票の基本情報をAI用指示文から分ける構成
- 確認した記録を既存レイアウトのDOCXへ出力する処理
- ローカル版のSQLite保存・版の衝突検知・重複DOCXの取込防止
- デモ版の認証・CSRF確認・入力サイズ制限・同時実行時の月間回数制限

入口となるファイル：

- [`demo/worker/server.js`](demo/worker/server.js)：ログイン・セッション・API・利用制限
- [`demo/public/demo.js`](demo/public/demo.js)：一時保存と見本・AI連携の画面処理
- [`demo/public/record.js`](demo/public/record.js)：入力確認・DOCX・和暦出力
- [`local-app/server.py`](local-app/server.py)：ローカルHTTPサーバーとGemini連携
- [`local-app/records_store.py`](local-app/records_store.py)：SQLite・DOCX取込・PDF・月次出力

## 現在の制約

公開版は `gemini-2.5-flash` を参照しており、以前の公開環境テストではモデル利用不可による失敗を確認しています。ローカルにある `gemini-3.5-flash-lite` への未公開変更は、承認されていない自動検索の変更も含むため、公開中のコードへ混ぜていません。この移行ではAIを課金実行していません。

公開版のAI試行はサイト全体で月5回までで、失敗も回数に含みます。入力18,000バイト・32,000トークン、出力2,048トークンの制限があります。月100円は追加費用の目標であり、為替・検索回数・料金変更を含む円建ての請求上限を保証する設定ではありません。

実記録、個人情報、勤務先の非公開情報をデモへ入力しないでください。公開版のAI生成を操作すると、確認した指示文がGemini APIに送信されます。
